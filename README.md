# DocuMind

> 개인 문서를 안전하게 정리하고, 출처와 함께 답변받는 AI 지식관리 서비스

---

## 1. 프로젝트 개요

### 1.1 문제 정의

개인과 소규모 팀은 PDF, 회의록, 강의자료, 업무 문서가 여러 위치에 흩어져 있어 필요한 정보를 찾는 데 많은 시간을 사용한다. 일반적인 AI 챗봇은 답변은 빠르지만 어떤 문서를 근거로 답했는지 확인하기 어렵다.

**DocuMind**는 사용자가 업로드한 문서만을 검색해 질문에 답하고, 답변의 근거가 된 문서명과 페이지를 함께 보여주는 문서 기반 AI 지식관리 서비스다.

### 1.2 핵심 가치

- 문서를 한곳에서 관리한다.
- 키워드와 의미 기반 검색을 함께 제공한다.
- 답변마다 출처를 표시해 검증 가능하게 한다.
- 사용자가 답변 품질을 평가해 검색 결과를 개선한다.

### 1.3 대상 사용자

- 강의자료와 논문을 정리하는 대학생
- 회의록과 업무 문서를 관리하는 직장인
- 내부 매뉴얼과 기술문서를 관리하는 소규모 팀

## 2. 목표와 범위

### 2.1 최종 목표

사용자가 문서를 업로드하고 질문하기까지 3분 이내에 완료할 수 있으며, 답변에서 근거 문서를 즉시 확인할 수 있는 웹 서비스를 구현한다.

### 2.2 MVP 범위

| 구분 | 포함 기능 | 완료 기준 |
|---|---|---|
| 사용자 | 회원가입, 로그인, 로그아웃 | 인증된 사용자만 자신의 문서 접근 가능 |
| 문서 | PDF/Markdown 업로드, 목록, 삭제 | 최대 20MB 파일을 업로드하고 상태 표시 |
| 처리 | 텍스트 추출, 문서 분할, 임베딩 생성 | 처리 성공/실패 상태를 사용자에게 표시 |
| 검색 | 키워드 검색, 의미 기반 검색 | 검색어에 맞는 상위 5개 청크 반환 |
| 질의응답 | 문서 기반 질문 및 답변 | 답변과 출처 문서명/페이지를 함께 표시 |
| 평가 | 답변 좋아요/싫어요, 피드백 메모 | 평가 결과를 저장하고 질문 기록에서 확인 |
| 기록 | 질문 기록 조회 및 삭제 | 사용자별 최근 질문 50개 조회 가능 |
| 안정성 | 파일 형식/크기 검증, 오류 메시지 | 잘못된 입력이 서버 오류로 노출되지 않음 |

### 2.3 MVP에서 제외하는 기능

- 실시간 협업 편집
- 모바일 네이티브 앱
- 이미지와 표의 완전한 구조 보존
- 외부 웹페이지 자동 수집
- 팀 단위 권한 관리
- 모델 자체 파인튜닝

## 3. 주요 사용자 시나리오

### 시나리오 A: 문서 등록

1. 사용자가 로그인한다.
2. PDF 또는 Markdown 파일을 선택한다.
3. 서버가 확장자와 파일 크기를 검증한다.
4. 문서가 `processing` 상태로 등록된다.
5. 텍스트 추출, 청크 분할, 임베딩 생성이 완료된다.
6. 문서 상태가 `ready`로 변경된다.
7. 처리 실패 시 `failed` 상태와 재시도 안내를 표시한다.

### 시나리오 B: 문서 질문

1. 사용자가 질문을 입력한다.
2. 시스템이 질문을 임베딩으로 변환한다.
3. 사용자 문서 안에서 관련 청크를 검색한다.
4. 상위 청크를 AI 모델에 컨텍스트로 전달한다.
5. 모델이 답변과 출처 목록을 생성한다.
6. 화면에 답변, 문서명, 페이지 번호, 관련 문장 미리보기를 표시한다.

### 시나리오 C: 근거 없는 질문

검색된 문서에서 답을 찾지 못한 경우, 시스템은 추측하지 않고 다음과 같이 응답한다.

> 업로드된 문서에서 답변의 근거를 찾지 못했습니다.

## 4. 기능 명세

### 4.1 문서 상태

```text
uploaded -> processing -> ready
                    \-> failed
```

| 상태 | 의미 |
|---|---|
| `uploaded` | 파일 저장 완료, 분석 대기 |
| `processing` | 텍스트 추출 또는 임베딩 생성 중 |
| `ready` | 검색과 질문 가능 |
| `failed` | 처리 실패, 오류 원인과 재시도 버튼 표시 |

### 4.2 답변 생성 규칙

- 검색 결과에 포함된 내용만 근거로 사용한다.
- 근거가 부족하면 모른다고 답한다.
- 답변에는 최소 1개의 출처를 포함한다.
- 출처에는 문서명과 페이지 또는 청크 위치를 표시한다.
- 사용자의 문서에 없는 내용을 사실처럼 생성하지 않는다.
- 답변 생성 실패 시 검색된 원문을 노출하지 않고 재시도를 안내한다.

### 4.3 검색 기준

- 기본 검색 결과: 상위 5개 청크
- 청크 크기: 500~800 토큰
- 청크 중첩: 80~120 토큰
- 최소 유사도 임계값: 0.70
- 동일 문서의 중복 결과: 최대 3개
- 검색 응답 목표 시간: 2초 이내
- 답변 응답 목표 시간: 10초 이내

## 6. 권장 기술 스택

| 영역 | 기술 | 선택 이유 |
|---|---|---|
| Frontend | Next.js, TypeScript | 화면과 API 연동, 타입 안정성 |
| UI | Tailwind CSS | 일관된 반응형 UI 구현 |
| Backend | FastAPI, Python | 문서 처리와 AI 라이브러리 연동 |
| Database | PostgreSQL | 사용자, 문서, 질문 기록 저장 |
| Vector Search | pgvector | PostgreSQL 안에서 벡터 검색 구성 |
| File Storage | Azure Blob Storage 또는 로컬 저장소 | 원본 문서 보관 |
| AI Model | OpenAI API 또는 Azure OpenAI | 임베딩과 답변 생성 |
| 인증 | JWT 또는 세션 기반 인증 | 사용자별 문서 접근 제어 |
| 테스트 | Pytest, Playwright | API 단위 테스트와 주요 사용자 흐름 검증 |
| 실행 환경 | Docker Compose | 로컬 개발 환경 통일 |

### 6.1 초기 개발 환경

외부 클라우드 비용을 줄이기 위해 초기 개발은 다음과 같이 진행한다.

- PostgreSQL + pgvector: Docker Compose
- 파일 저장: 로컬 `storage/` 디렉터리
- AI API 키: `.env`로 주입
- 운영 배포 시 파일 저장소를 Azure Blob Storage로 교체

## 10. 테스트 기준

### 기능 테스트

- 지원하지 않는 확장자 업로드가 거부되는가?
- 20MB 초과 파일이 거부되는가?
- 다른 사용자의 문서 ID를 입력해도 접근할 수 없는가?
- 처리 실패 문서를 재시도할 수 있는가?
- 문서 근거가 없는 질문에 추측성 답변을 하지 않는가?
- 답변 출처의 문서명과 페이지가 실제 문서와 일치하는가?
- 질문 기록과 평가가 새로고침 후에도 유지되는가?

### 성능 목표

| 항목 | 목표 |
|---|---:|
| 문서 목록 응답 | 500ms 이하 |
| 일반 검색 응답 | 2초 이하 |
| AI 답변 응답 | 10초 이하 |
| 10MB PDF 처리 | 60초 이하 |
| 동시 질문 처리 | 5건 이상 |

### 보안 테스트

- 비밀번호 평문 저장 여부 확인
- 인증 토큰 없는 API 접근 차단
- 파일명 기반 경로 조작 차단
- HTML/스크립트 입력 저장 시 이스케이프
- 사용자 간 문서와 질문 기록 격리
- API 키가 프론트엔드에 노출되지 않는지 확인

## 12. 성공 기준

다음 조건을 모두 만족하면 MVP 완료로 판단한다.

- 회원가입 후 로그인할 수 있다.
- PDF 또는 Markdown 문서를 업로드할 수 있다.
- 문서가 처리 완료 상태로 전환된다.
- 업로드한 문서에 대해 질문할 수 있다.
- 답변에 실제 근거 문서와 위치가 표시된다.
- 근거 없는 질문에는 답변을 거부하거나 한계를 명시한다.
- 사용자별 데이터가 서로 노출되지 않는다.
- 핵심 사용자 흐름에 대한 자동 테스트가 통과한다.
- 로컬 환경에서 한 번의 명령으로 실행할 수 있다.
